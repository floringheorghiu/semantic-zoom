# Remove Zoom Layers — Design

Date: 2026-07-17
Status: approved (brainstorming session, session "Semantic Zoom - delete JSON payload")

## Purpose

Generating zoom layers must be reversible. This feature lets the user strip the embedded `<!-- semantic-zoom:payload:v1 ... -->` block from a markdown file, returning it to its raw pre-generation state. The action is gated behind a native macOS confirmation dialog. The document's generation history (the sidecar run records) is never touched by removal — history survives, and the removal itself becomes a history event.

## Constraints honored

- **Rust owns disk truth.** The file rewrite happens in a new Rust command, mirroring `write_payload`. The frontend never edits the file.
- **No `@tauri-apps/*` imports under `src/ui/**` or `src/engine/**`.** The tooltip component exposes a callback; `main.ts` owns the dialog and the invoke.
- The payload block is located with the parser's existing genuine-payload scanner (the one that survives decoy `<!--` occurrences in prose), so what is removed can never disagree with what the loader would have displayed.

## Components

### 1. Rust command `remove_payload` (`src-tauri/src/commands/remove_payload.rs`)

Signature: `remove_payload(path: String) -> Result<RemovePayloadOutcome, String>`.

- Re-reads the file from disk at invoke time.
- Locates the genuine payload block via the parser's existing scanner (`parser::payload`). No genuine payload → returns `NoPayload` outcome (not an error; the file may have changed underfoot, and "already gone" is success for this operation).
- Rewrites the file as just the raw content, using the same `write_atomically` (write-then-rename) helper `write_payload` uses. The padding blank line added at generation time is stripped too, so the file ends with a single trailing newline — byte-identical to the pre-generation file in the normal case.
- Appends a `removed` event to the generation-history sidecar so the per-document history reads "generated → … → removed" over time.
- Outcomes: `Removed`, `NoPayload`. IO failures are `Err` and leave the file untouched.

### 2. Native confirmation dialog (`main.ts`)

Uses `@tauri-apps/plugin-dialog` `ask()` (plugin already installed, `dialog:default` already granted in the default capability). Title "Remove zoom layers?"; message states that the generated summaries will be deleted from the file but the raw markdown and the generation history are untouched; confirm button "Remove" (destructive style), Cancel is the default. Only on confirm is `remove_payload` invoked.

### 3. UI entry point (`generation-tooltip.ts`)

The history tooltip card (opened from the permanent status pill) gains a second, independent region:

- **History region:** the run list as today. When there are zero runs but the document is tagged, an empty state replaces the list: "No generation history for this file — its zoom layers were created before history tracking, or outside this app."
- **Action region:** a "Remove zoom layers…" button, shown whenever the current document is tagged, regardless of history.

The card's open condition changes from "has runs" to "has runs OR document is tagged". This covers the edge case of files tagged before the history feature existed (payload present, zero run records): they get the empty state plus the Remove button. Untagged file with no history: no card, unchanged. Untagged file with history (i.e., after a removal): card opens with past runs, no Remove button.

The button dispatches to a callback provided by `main.ts`; the component itself stays Tauri-free.

### 4. Post-removal flow (`main.ts`)

The directory watcher deliberately ignores writes that leave the raw-content hash unchanged — and removing the payload does exactly that. So `main.ts` explicitly re-invokes `load_document` after a successful removal. The document comes back `Untagged`; the existing rendering path shows raw markdown, the zoom scrubber hides, and the Generate affordance reappears — regeneration is one click away, which is what makes the cycle reversible. The status pill flashes "Zoom layers removed".

## Error handling

- File unreadable/unwritable: `Err` from the command; surfaced via the status pill's failure toast; file untouched.
- File changed between confirm and write: the command operates on current bytes; if the payload is already gone, `NoPayload` is treated as success and the reload proceeds.

## Testing

- Rust unit tests in `remove_payload.rs`: round-trip (write payload → remove → bytes equal original), no-payload no-op, decoy-marker safety (prose containing the marker text is not stripped), refused write leaves file untouched.
- TS tests for `generation-tooltip.ts`: card opens for tagged doc with empty history showing empty state + button; button hidden for untagged docs; callback fires on click.
- Manual acceptance: generate on a fixture copy, remove, confirm file bytes match the original and the app shows raw markdown with Generate visible; history card still lists the prior run plus the removal event.
