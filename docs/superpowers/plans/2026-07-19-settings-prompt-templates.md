# Settings Restructure & Summarization Templates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tabbed settings window (General / Prompt / Inference) with UI quality-of-life controls, plus user-editable summarization templates injected into Engine B's editorial layer — the format contract stays locked.

**Architecture:** The settings webview stays a bundle-alone module tree (`src/native/settings/`), talking to Rust only via existing-pattern commands on `provider-config.json` and the generation-history sidecar. View-truth prefs (theme, accent, anchor visibility, current-doc path) use the `theme.ts` localStorage + `storage`-event pattern to sync across the two webviews. `synthesis-prompt.mjs` splits into locked CONTRACT_HEADER/FOOTER around a swappable editorial block.

**Tech Stack:** Tauri v2, Rust (serde), vanilla TypeScript, Vitest, cargo test.

**Spec:** `docs/superpowers/specs/2026-07-19-settings-prompt-templates-design.md`

## Global Constraints

- No `@tauri-apps/*` imports under `src/engine/**` or `src/ui/**` (ESLint-enforced). `src/native/**` MAY import `@tauri-apps/api/core`.
- The settings bundle (`settings-form.ts` and everything under `src/native/settings/`) must never import viewport, store, or engine modules.
- Animate `opacity` only. The anchor-ID toggle and accent swap are instant class/property changes — never add a `transition` for them.
- Format contract is locked: HARD RULES, TASK step 1 (grouping), OUTPUT SHAPE must be byte-identical in every assembled system prompt regardless of template.
- All new serde fields take `#[serde(default)]` (plus `skip_serializing_if` where the field is optional) so pre-existing JSON files deserialize cleanly.
- Never hand-author `P-`/`S-` ids (D6). Nothing in this plan touches payloads.
- Run suites with quiet output per project practice: `npx vitest run <file> 2>&1 | tail -5`, `cargo test -q <name> 2>&1 | tail -5`.
- Each PR ends with a manual WebKit pass by the user — a background session cannot run it. State "implemented, awaiting WebKit pass" honestly.
- Work each PR in its own worktree named for the task (e.g. `settings-tabs-general`, `prompt-templates-global`, `prompt-template-per-doc`).

```ts
// tabs.ts — segmented-control tab switching for the settings window.
// Pure show/hide over one bundle; no per-tab entry points.
export function initTabs(root: HTMLElement): void {
  const buttons = Array.from(root.querySelectorAll<HTMLButtonElement>('[role="tab"][data-tab]'));
  const panels = Array.from(root.querySelectorAll<HTMLElement>('section[data-tab]'));
  const select = (name: string) => {
    for (const b of buttons) b.setAttribute('aria-selected', String(b.dataset.tab === name));
    for (const p of panels) p.toggleAttribute('hidden', p.dataset.tab !== name);
  };
  for (const b of buttons) b.addEventListener('click', () => select(b.dataset.tab!));
}
```
