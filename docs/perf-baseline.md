# Semantic Zoom — Performance Baseline (Task 3.4)

This records the Phase-1 performance budgets from spec §7 and the measurements
taken against a synthetic 1 MB / 10,000-paragraph document.

> **Honesty note (headless measurement).** These numbers were produced in a
> headless environment. Only the **native Rust extraction** budget is measurable
> without the GUI, and only it is filled in below with real numbers. The two
> frontend budgets (**mask frame ≤16 ms**, **level-swap end-to-end ≤250 ms**)
> require the running Tauri app + Instruments and are left as **TBD — measure on
> target hardware**, with the exact procedure documented in the last section.

## Budgets (spec §7 / Task 3.4)

| Budget | Target | Where measured | Status |
| --- | --- | --- | --- |
| Native payload extraction | ≤ 10 ms | Headless (Rust test) | **PASS** — see below |
| Focus-mask frame | ≤ 16 ms | Running app (Instruments) | TBD (measure on target hardware) |
| Level-swap end-to-end | ≤ 250 ms | Running app (`performance.now()`) | TBD (measure on target hardware) |

## Machine

- CPU: **Apple M1 Max**
- Arch: **arm64** (Apple Silicon)
- Build: `cargo test --release` (optimized)

## Synthetic document

Generated by `perf/gen-synthetic.mjs` → `perf/synthetic-1mb.md` (gitignored).

- Pre-payload markdown body: **1,120,841 bytes (~1.07 MiB)** — the visible doc.
- Total file size incl. payload: **3,951,279 bytes (~3.77 MiB)** — the embedded
  `LookupTable` JSON carries pre-rendered `html` for every node.
- Paragraphs (level 0): **10,000**
- Sections (level −1): **200**
- Meta (level −2): **10**
- IDs are D6-derived (`P-<sha256(spanBytes)[:8]>-<ordinal>`,
  `S-<sha256(headingBytes)[:8]>-<ordinal>`, meta positional `M1..`); the payload
  passes the Rust `validate()` + `verify_ids(pre_payload)` pipeline.

## Measured: native extraction (≤ 10 ms budget) — PASS

Test: `src-tauri/tests/perf_extract.rs` (`#[ignore]` by default so the normal
suite stays fast). It times `extract_payload` (byte-scan + `serde_json` parse +
`validate`) **plus** `verify_ids(pre_payload)` (recomputes all 10,000 paragraph
content hashes) over **N = 20** iterations with `std::time::Instant`.

Run it with:

```sh
node perf/gen-synthetic.mjs                                   # once, to create the artifact
cd src-tauri && cargo test --release -- --ignored perf_extract
```

Results (Apple M1 Max, release, 20 iterations):

| min | median | mean | max | budget | verdict |
| --- | --- | --- | --- | --- | --- |
| 7.172 ms | **7.524 ms** | 8.134 ms | 14.007 ms | ≤ 10 ms | **PASS** (median 7.524 ms) |

The budget is enforced on the **median** and only in release builds (debug builds
are not representative; the test skips the assertion under `debug_assertions`).
This figure includes the full `verify_ids` re-hash of all 10k paragraphs, which
the ≤10 ms happy path (spec §2.6) does not strictly require at extraction time —
so the real hot-reload short-circuit has additional headroom.

## Frontend budgets — measured in the running app (pending)

These CANNOT be measured headlessly. Perform them on target hardware (Apple
Silicon Mac) with the built app open on `perf/synthetic-1mb.md`.

### Setup

1. `node perf/gen-synthetic.mjs` to (re)generate `perf/synthetic-1mb.md`.
2. `npm run tauri dev` (or a release `.dmg` build), then open
   `perf/synthetic-1mb.md` in the app.

### Mask frame — ≤ 16 ms (spec §4.3 acceptance test)

The §4.3 acceptance test: open a large doc, hold ⌥ and arrow the caret across
group boundaries continuously for ~10 s while the focus mask remaps.

1. Launch **Instruments → Core Animation** (or **Time Profiler**) attached to the
   app process.
2. Start recording, then hold ⌥ and drive the caret across many group boundaries
   for ~10 s so the mask (`data-dimmed` toggling + token remap) runs repeatedly.
3. Inspect the timeline: **no main-thread frame > 8 ms** should be attributable
   to the mask (well under the 16 ms / 60 fps frame budget), and there should be
   **no memory growth** from layer promotion.

### Level-swap end-to-end — ≤ 250 ms (spec §7)

Measures a full zoom transition (e.g. level 0 → −1 → −2) including the two-frame
mount (D8) and keyed reconciliation (D7).

1. In the app, instrument the transition with `performance.now()`: capture a
   timestamp when the level-change is dispatched and another on the
   `transitionend` / first painted frame of the new level, and log the delta.
   (Alternatively, use an Instruments **Time Profiler** trace bracketing one swap.)
2. Trigger several level swaps on the synthetic doc and record the worst-case
