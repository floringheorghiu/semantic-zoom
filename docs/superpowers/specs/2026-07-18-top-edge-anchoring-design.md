# Top-Edge Anchoring, Caret Demotion, and Landing Highlight — Design

**Date:** 2026-07-18
**Status:** Approved verbally in session; this document is the written record for review.
**Amends:** `docs/Implementation_Plan.md` §2.5 (anchor resolution + centering math). Does **not** touch decisions D1–D8.

## Problem

Zoom jumps currently feel unpredictable for two reasons:

1. **Center-based anchoring.** The anchor is the node whose vertical center is closest to the viewport center, and the mapped target node is centered in the viewport. Readers track position by the *top* of the viewport (the same convention browsers use for scroll anchoring), so center-based jumps land "somewhere in the middle" relative to the reader's mental model.
2. **An invisible marker steers navigation.** Clicking a paragraph sets a `data-caret` attribute (`src/ui/caret.ts`) that has **no CSS styling anywhere** — it is invisible — yet it overrides anchor resolution on the next jump (`src/ui/viewport.ts:534`). The UI is steered by state the user cannot see.

## Design

### 1. Top-edge anchor resolution ("the red thread")

The anchor at the source level is the **topmost actually-visible node**:

- the node whose box contains the viewport's top edge, or, if the top edge falls in a gap,
- the first node whose top starts below the top edge.

Explicitly **not** "the node closest to the top edge": a node whose bottom scrolled 2px above the top edge is close but no longer being read. Implemented as a replacement for `resolveAnchor()` in `src/engine/anchor.ts`, still a single pass over cached `MountedBox` values — no live DOM reads.

### 2. Top-edge placement

`centerScrollTop()` is replaced by top-alignment: the mapped target node lands with its top just below the viewport's top edge.

```
scrollTop = clamp(el.offsetTop - GAP, 0, scrollHeight - clientHeight)
```

`GAP` is a small breathing space, initially 16px, tuned during the manual WebKit pass. The D8 two-frame mount discipline is unchanged — same measurement in frame n+1, different formula applied to it.

A pleasant consequence: the `-1 → 0` first-visit fallback (`sections[S].children[0]`) becomes natural — the section *begins* just below the top edge instead of having its first paragraph arbitrarily centered.

### 3. Caret demoted out of navigation

The caret override in anchor resolution is removed: `resolveAnchor()` no longer takes a caret parameter, and the `caretAnchor` computation in `runTransition()` (`src/ui/viewport.ts:528–535`) is deleted along with the `caretIsCurrent` plumbing that exists only to guard it. The topmost-visible rule is the *only* anchor rule.

The caret keeps its non-navigation jobs unchanged:

- click-to-spotlight (focus mask via `activeGroupHead`),
- arrow-key traversal across `.pnode`s.

**Remembered place survives.** `recordPlace()` writes `lastCaretIn`/`lastAnchorIn` from the resolved *anchor*, not from the caret, so zoom-out/zoom-in round-trips without scrolling still restore the exact paragraph. No change to `recordPlace()` or `mapAcrossLevels()`.

### 4. Transient landing highlight

After every zoom transition settles, the node that landed below the top edge gets a brief visual acknowledgment so the red thread is *visible*:

- a left accent bar (or outline — final form chosen visually) on the landed node,
- fades out over ~1s, animating **opacity only** (D1 — no filter/layout transitions),
- rendered as a class/attribute toggled by the transition's settle callback; removal on `transitionend` plus a timeout fallback,
- no persistent chrome and no scroll-tracking indicator in this iteration (deliberate: avoids per-scroll DOM writes; a persistent marker is a possible follow-up after living with the transient one).

## Out of scope

- Persistent / scroll-tracking anchor indicator (possible follow-up).
- Customizable summarization instructions (separate project, to be brainstormed after this ships).
- Any change to zoom levels, payload contract, IDs (D6), or the two-frame mount (D8).

| File | Change |
|---|---|
| `src/engine/anchor.ts` | `resolveAnchor()` → topmost-visible rule, caret param removed; `centerScrollTop()` → `topAlignScrollTop()` |

| `src/ui/viewport.ts` | drop caret-anchor plumbing; use top-align formula; trigger landing highlight on settle |

| `docs/Implementation_Plan.md` §2.5 | replace centering math + anchor rule with the above, same PR |

## Verification

- Unit tests: topmost-visible resolution (contains-top-edge case, gap case, node-scrolled-past case), clamping in `topAlignScrollTop`, round-trip place memory without caret involvement.
- Integration test: `0 → −1 → 0` without scrolling restores the exact paragraph top-aligned; scrolling at −1 to a new section then `→ 0` lands on that section's first paragraph top-aligned.
- Manual WebKit pass (standing rule: Chrome verification is insufficient) — feel of the GAP value, highlight visibility in light/dark themes.
